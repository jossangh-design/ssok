# 쏙 (Ssok)

사진·PDF·한글(hwp·hwpx) 파일의 용량을 **목표에 맞춰** 줄이는 윈도우 프로그램입니다. 학교에서 "5MB 이하로 올려 주세요" 같은 제출 조건을 맞출 때 씁니다.

- 이 PC 안에서만 처리합니다. 파일을 인터넷으로 보내지 않습니다.
- 원본은 그대로 두고, 줄인 결과는 웹하드처럼 **체크해서 다운로드**합니다. 1개는 `원래이름_쏙.jpg`로, 여러 개는 `쏙_첫파일 외 N개_날짜.zip` 하나로 저장되고, 줄 끝 ⬇ 단추로 하나씩 받을 수도 있습니다. 저장 뒤에는 탐색기가 열려 저장한 파일을 보여 줍니다.
- 사진을 다시 저장할 때 촬영 위치(GPS) 정보는 지웁니다.
- 관리자 권한이 필요 없습니다.

## 내려받기

[**최신 버전 내려받기**](../../releases/latest)

- **설치판(추천)** `Ssok-Setup-버전.exe` — 실행하면 바로 설치됩니다. 관리자 권한이 필요 없고, 새 버전이 나오면 쏙 안에서 버튼 하나로 업데이트됩니다.
- **무설치판** `Ssok-Portable-버전.zip` — 압축을 풀고 `Ssok.exe`를 실행하세요.
- Windows 10(1809) 이상, 64비트.

## 지금 되는 것 (0.4)

| 파일 | 방법 |
| --- | --- |
| JPG | 품질을 낮추고, 그래도 크면 가로·세로를 줄여 목표 이하로 맞춤 |
| PNG | 가로·세로를 줄여 목표 이하로 맞춤 (투명 배경 유지) |
| HEIC·WebP·BMP | JPG로 바꿔 저장 (HEIC·WebP는 Windows 이미지 확장 필요) |
| hwpx | 문서 속 그림(JPG·PNG·BMP·GIF)만 다시 압축. 투명한 곳이 없는 그림은 JPG로 바꾸고 문서 목록(content.hpf)도 함께 고침. 글자·표·서식은 그대로 |
| hwp | 문서 속 그림(JPG·PNG·BMP·GIF)만 다시 압축. 투명한 곳이 없는 그림은 JPG로 바꾸고 DocInfo의 확장자도 함께 고침. 그림마다 원래 압축 방식 유지 |
| PDF | 먼저 문서 속 JPEG·화소 그림만 다시 압축 (qpdf, 글자 유지). 그래도 목표에 못 미치면 쪽마다 그림으로 바꿔 목표에 맞춤 (200dpi·화질 85% → 30dpi·22% 중 가장 선명한 단계, 윈도우 내장 PDF 렌더러) |

- 목표 용량은 **파일마다** 또는 **모두 합쳐서** 정할 수 있습니다. 합쳐서 모드는 파일 하나를 끝낼 때마다 남은 용량을 다시 나눕니다.
- 사진 저장 형식(원래대로·JPG·PNG)은 전체로 정하고, 파일마다 따로 바꿀 수도 있습니다.
- '사진 속 위치정보 지우기'를 켜면 촬영 장소(GPS)·카메라 정보를 빼고 저장합니다. 끄면 JPG의 부가 정보를 그대로 옮깁니다.
- PDF '흑백으로 바꾸기'를 켜면 PDF 속 그림을 흑백으로 바꿔 더 줄입니다. 글자는 그대로입니다.
- 마지막으로 쓴 설정은 `%AppData%\Ssok\settings.json`에 기억합니다 (파일 이름·경로는 저장하지 않음).
- 사진은 글자를 알아볼 수 없을 만큼 줄이지 않습니다 (JPG 품질 50 미만, 짧은 쪽 240픽셀 미만 금지).
- 문서는 16단계(긴 쪽 4096→320픽셀, 품질 88→40) 중 목표를 맞추는 가장 약한 단계를 고릅니다. 가장 세게 줄여도 못 미치면 그 결과를 "목표 미달"로 저장합니다.
- **모두 합쳐서** 모드에서 더 줄일 수 없는 파일이 있으면, 여유가 있는 다른 파일을 더 줄여 합계를 맞춥니다.
- 암호·배포용·전자서명 문서, 암호 PDF는 바꾸지 않습니다.
- 아직 안 되는 것: PDF의 CMYK 그림, hwp 3.0 이전 문서.

## 만들기

`build.cmd`를 두 번 누르면 됩니다.

1. .NET 10 SDK가 없으면 설치합니다.
2. qpdf 공식 배포본을 받아 지문(SHA-256)을 확인합니다.
3. 핵심 기능 시험을 돌립니다.
4. `dist` 폴더에 `Ssok.exe`, `qpdf` 폴더, 라이선스 파일을 만듭니다. 다른 PC에 .NET이 없어도 실행됩니다.
5. 만든 프로그램으로 실제 hwp·hwpx·PDF·사진을 줄여 보는 자가 시험을 합니다.

6. `release` 폴더에 무설치판 zip을 만들고, Inno Setup 6이 있으면 설치판도 만듭니다.

진행 기록은 `build-log.txt`, 자가 시험 결과는 `build-selftest.txt`에 남습니다.

공식 배포 파일은 GitHub Actions가 만듭니다. `v0.4.0`처럼 태그를 올리면 설치판·무설치판·업데이트 정보(`update.json`, 서명 포함)를 만들어 Releases에 올립니다. 자세한 순서는 [DEPLOY.md](DEPLOY.md)를 보세요.

## 개발 원칙

- 문서 파일과 그 내용은 인터넷으로 보내지 않는다. 네트워크 코드는 업데이트 기능(`Updater.cs`)에만 둔다.
- 업데이트 정보는 배포용 비밀 키로 서명하고, 쏙은 서명과 설치 파일 지문(SHA-256)이 맞을 때만 설치한다.
- 원본 파일은 절대 수정하지 않는다.
- 로그에 파일 이름·경로·문서 내용을 남기지 않는다.
- MIT, Apache-2.0, BSD, MPL-2.0 라이선스 부품만 쓴다. AGPL·GPL 부품은 쓰지 않는다.
